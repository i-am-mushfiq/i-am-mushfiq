### Undergraduate thesis

<table>

<td>

<img alt="Undergraduate thesis" src="https://img.shields.io/badge/UNDERGRADUATE_THESIS-4b3f9e?style=flat-square" />

**Orthographic Gaussian Splatting from CT Radiographs**<br>
<sub>3D RECONSTRUCTION · MEDICAL IMAGING · NEURAL RENDERING</sub>

Gaussian Splatting pipelines are built around perspective cameras. CT data isn't captured that way. This work adapts Gaussian Splatting to **orthographic projection geometry** and applies it to clinical CT sequences, where the projection model and the reconstruction problem impose constraints that conventional pipelines aren't designed around.

**Code** &nbsp;→&nbsp; [3dgs-brain-ct-visualisation](https://github.com/i-am-mushfiq/3dgs-brain-ct-visualisation) &nbsp;·&nbsp; [sparse-view-gaussian-tomography](https://github.com/i-am-mushfiq/sparse-view-gaussian-tomography)

Reinforcement learning for **spacecraft proximity operations**. The question isn't only whether an agent can learn a policy. It's whether that policy can operate within **hard physical and safety constraints** while staying useful under realistic dynamics.

## Approach

I don't find a strict line between research and engineering useful. A paper without implementation can remain speculation. An implementation without theoretical grounding can remain fragile. The interesting work happens when each constrains the other.

I'm drawn to systems where **the failure modes are non-obvious, the feedback loop is slow, the constraints are real**, and the result has to work outside a controlled demo. That applies equally to a rover in a field, a model operating under safety constraints, or a financial system where a single incorrect state can propagate through an entire transaction lifecycle.
